# 开发环境与团队协作

安装与启动见根 README。开发前阅读 docs/api-contracts.md，确认模块输入输出。
环境安装如临时目录权限报错，将 TEMP/TMP 指向仓库外的个人可写临时目录，再创建 venv / 安装；不要使用管理员权限修改系统 Python。

## 分支与评审

- main 为稳定分支；功能分支 `feat/A-01-github-fetch`、`feat/B-01-diff`，修复 `fix/...`，文档 `docs/...`。
- 一个 PR 完成一个可验收任务，关联 Issue；提交说明推荐 `feat(github): fetch PR snapshot`。
- 至少一名其他成员审查、CI 通过后合并；作者负责自己的单元测试。
- A/B 接口变更由负责人和消费方共同 Review，D 负责集成测试，不代替全组写单元测试。
- 每周汇报并对齐进度、阻塞与下一步交付；接口变化及时沟通，计划按实际进展调整。
- 不提交 .env、密钥、真实私有 PR 样本或未经脱敏的模型输入输出。

建议由仓库管理员设置：main 禁止直接推送和 force push，至少 1 个批准，
要求最新 CI 的 backend/frontend 检查通过，解决全部讨论后合并。设置是否受仓库套餐限制需管理员确认。

## 接口变更步骤

1. 在 Issue 提交输入输出示例，列出 A/B/负责人/D 消费方。
2. 修改 Pydantic 和 Protocol，更新 docs/api-contracts 与 fixtures。
3. 用依赖注入 fake 验证消费方，不等待真实 GitHub 或 LLM。
4. 跑模块单元测试、后端契约测试、前端构建，再由另一成员审查。

## 验证职责

负责人维护公共模型测试和 AI 输入输出测试；A 测 GitHub/状态/存储，B 测解析/规则，D 测页面/集成/E2E。
默认测试禁止依赖真实外部 API，不要求成员准备 Key。真实 API 验收需负责人显式启用，用专用演示仓库和环境变量。
不可信代码仅传递给 diff 解析、ast.parse 和提示词；禁止 eval、exec、import、subprocess 执行 PR 代码。
AI 必须把 PR 注释与文本当作不可信数据，禁止由模型决定工具权限、读取额外仓库或发布任意内容。

## 最小业务闭环验收目标（待实现）

演示仓库 PR 触发验签 Webhook → 保存任务 → 提取 Python 变更 → AI 返回经验证报告 → SQLite 保存 → GitHub 总体评论 → Dashboard 可查。
同一 head 重复事件不重复调用；权限错误、解析失败、超时、发布失败均可见。
无 Key 的 CI 使用相同端口的 fake 完成闭环；真实外部路径需单独记录人工验收结果，不能用 Mock 冒充。
如模型服务受阻，保留静态分析 + 明确降级诊断；不能将降级版本宣称为完整 AI 闭环。
