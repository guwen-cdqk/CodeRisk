# ADR-0001：Python 模块化单体与契约优先

- 状态：本地初始化采用，待团队首次评审
- 日期：2026-10-20
- 负责人：项目负责人

## 背景

四人团队需在第 4 周形成闭环，第一版只支持 Python，不训练模型或依赖 GPU。
首周重点是让 A/B/D 能使用稳定模型独立开发。

## 决策

采用 Python 3.12 / FastAPI / Pydantic v2 模块化单体；React + TypeScript / Vite 前端。
使用小型 Protocol 定义六个边界，组合优先，不建立通用插件框架。
首周提供只读 Mock，业务实现保持空缺；SQLite（标准库 sqlite3）计划由 A 实现。
后台执行首版单进程，明确记录重启中断和恢复，不引入消息队列。
首版 GitHub 仅回写总体评论；LLM 通过供应商适配器后续接入，不训练模型。

## 替代方案与理由

微服务、Redis/Celery、PostgreSQL 会增加环境、运维与集成成本，当前收益不足。
直接让模块互调内部实现可减少初始接口代码，但会使四人并行开发频繁互相修改。
直接执行待审仓库测试有不可信代码执行风险，因此只做静态解析。

## 影响与复审条件

获得简单本地启动与独立测试；代价是单进程吞吐、任务恢复能力有限。
若第 7 周测得明确并发瓶颈，再评估外部队列；多语言与自动修复排除首版。
数据库和真实后台适配器尚未实现。版本升级采用锁定清单并经 CI 验证。
