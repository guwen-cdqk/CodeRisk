# C：AI 审查与架构协调

更新：2026-10-25。
[文档导航](../../README.md#documentation) · [架构](../architecture.md) · [公共接口](../interfaces.md) · [协作流程](../development.md)

## 1. 我负责什么

根据代码变更、函数上下文和静态证据生成有用、可核对的候选审查意见，同时作为项目负责人协调接口和集成。
统一入口 AIReviewer.review 接收 task_id、PR 和 AnalysisResult，返回 ReviewReport。
不获取 PR、不创建任务、不写库、不发布评论；模型不获得额外工具权限。

## 2. 从哪些文件开始

先读 `backend/app/schemas/models.py`、`services/contracts.py` 和 `core/errors.py`；与 A 确定模型服务的配置入口。
按需创建 `reviewers/ai_reviewer.py`、`provider.py`、`prompts.py`、fake 与 `backend/tests/` 中的模型响应测试。
公共字段由 C 协调但不独自决定；消费方和实现者共同 Review。

## 3. 当前阶段任务

### C-01 · P0 · Fake Reviewer 与共同样例

先实现同签名 fake，使用合法 PR/分析样例返回固定报告，明确 is_mock=true，不要求 Key。
交付入口、fake 和共同 fixture；task_id/SHA 不变，静态发现与诊断保留，A 可独立验证协调流程。
与 A/B/D 共用样例，不维护四套含义不同的“同一个 PR”。

### C-02 · P0 · 模型适配与受控输入

选择一个 provider，整理相关函数/变更/证据，使用环境凭证、有限超时/重试、上下文和费用预算。
依赖 C-01；交付 provider、提示词版本及安全配置示例。局部逻辑和异常处理也在目标内，不只是复述规则。
fake 响应覆盖正常、坏 JSON、未知字段、超时、限流。默认测试不调用模型、不记录完整私有输入。
模型/预算和数据发送范围先与维护者确认，其他成员无需持有 Key。

### C-03 · P0 · 证据校验、合并和降级

在结构校验后核对文件、old/new 侧、真实行范围、证据和变更关联性，去重并保留有效静态发现。
依赖 C-02 和 B 的结果约定；交付输出校验、报告组装与故障测试。虚构位置、错证据不能直接发布。
模型不可用或整体无效而静态分析可用时，保留静态结果并明确降级，静态发现为零也不代表完整成功。
具体状态/validator 与 A/D 按 [Q-05](../decisions.md#q05)评审；当前 Schema 还不支持 degraded。

### C-04 · P1 · 质量与对照实验

与 B 固定人工复核样例，比较静态、Diff-only LLM、上下文+证据校验，记录有效发现、误报/漏报、位置错误、耗时和费用。
交付可复现配置、模型/提示词标识和回归。数据、标签匹配和参数先定，再比较；不把模型自评当真值。
公共报告元数据若需新增，由 A/C/D 一起更新模型和展示，不往严格 Schema 塞任意字段。

## 4. 首个 PR

先做 C-01，让 A 无需等待模型和 B 真正完成就能联调；不提前写完整 LLM 流程。
请 A Review 调用/错误契约，B Review 静态发现保留，D 核对示例可展示。

## 5. 协调职责与依赖

主持每周短汇报，处理跨模块阻塞；公共接口和重要决策确认后同步代码与对应文档。
B 提供上下文与位置，A 传任务并保存，D 展示证据与限制。重点先冻结 Q-05，避免各自改状态和快照字段。
不代替 A 实现全部后端，也不代写其他成员单测；五周是参考目标，不是逐周硬性工期。

## 6. 自己必须完成的测试

坏结构、未知字段、超时、非法路径/行、旧侧证据、静态/AI 去重、空结果与降级；加入提示注入和条件不足的样例。
PR 描述、代码和注释都是不可信数据，不允许它们改变系统权限。
证据能核对不保证判断正确，输出应说明触发条件和不确定性；真实模型效果另做人工评估。
