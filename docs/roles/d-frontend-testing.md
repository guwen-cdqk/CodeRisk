# D：前端、集成测试与部署

更新：2026-10-25。
[文档导航](../../README.md#documentation) · [架构](../architecture.md) · [公共接口](../interfaces.md) · [协作流程](../development.md)

## 1. 我负责什么

让用户通过网页提交 PR、阅读任务/报告/历史，并保证前后端和各业务模块能一起运行。
负责页面测试、跨模块集成、浏览器 E2E、CI 和部署基线；各成员仍负责自己模块的单元测试。

## 2. 从哪些文件开始

当前 `frontend/src/main.tsx` 包含页面和简单导航，`api.ts` 管 HTTP/展示类型，`style.css` 管样式，`vite.config.ts` 管代理。
按需拆 `pages/`、`components/`，选择一种轻量测试方案。当前 TS 类型只是字段子集，需与公共模型核对。
同时维护两端 Dockerfile/Compose、`.github/workflows/ci.yml` 和后续跨模块测试；真实业务和容器启动尚未完成验证。

## 3. 当前阶段任务

### D-01 · P0 · 页面与手动入口

基于现有 Mock 做列表→详情、历史入口及必要组件；再增加仓库+PR 编号提交表单。
交付页面和状态测试：加载、空、错误、失败、降级、Mock 清楚，发现展示位置/证据/原因/建议。
当前 POST 返回 501，应显示未接通，不能假造任务；后端未就绪时用明确 fake 测试受理流程。
证据作为转义文本显示，不直接插入源码或模型生成的 HTML；空发现不写“代码安全”。

### D-02 · P0 · API、状态和重试

统一 client，补齐或生成 TS 类型，接 A 的真实查询/提交，支持分页与有停止条件的刷新。
交付错误和页面测试：区分 404/409/422/503，终态停止轮询，卸载取消旧请求，避免旧响应覆盖新页面。
按已评审方案显示审查/发布两种状态，提供 [Q-07](../decisions.md#q07)的重试交互；重试时旧报告标为上次结果。
统计注明当前查询范围，不能把当前页数量当全库统计；新聚合 API 由 A 实现后再使用。

### D-03 · P0 · Docker 与可复现启动

实测现有容器配置、前端代理、后端健康等待，与 A 配好后续 SQLite 卷、数据路径及重启验证。
交付更新过的真实启动/停止/恢复步骤，维护在协作流程相应位置。另一成员能从干净环境复现。
凭证不进入镜像或工件，Vite 开发服务器不直接充当公网生产部署；共享访问保护先与 A/维护者确认。

### D-04 · P0 · 跨模块与浏览器 E2E

使用真实 A/B/C 内部实现，加 fake GitHub/LLM，串通提交/事件、分析、保存、HTTP 和列表→详情，逐步接入 CI。
交付链路测试、故障工件和 CI 命令。覆盖重复事件、错误签名、分析失败、模型降级、发布失败，无需真实 Key。
只调用 MockReadStore 不算业务 E2E；真实外部 GitHub/模型验收需专用授权环境，另外记录。
各作者修复自己的模块，D 维护整条验证链。

### D-05 · P1 · 稳定性与演示

补长报告、网络中断、历史筛选、备份恢复和演示脚本，协助 B/C 固定实验运行版本。
交付可复现演示与已知限制。结果明确区分真实、Mock 和降级，不把占位统计当完成能力。

## 4. 首个 PR

先交列表→详情和加载/错误/空态，直接使用当前 GET；第二个小 PR 做提交表单与 501/fake 受理状态。
不等待完整 GitHub/AI 接入，也不先做复杂 UI。A Review HTTP，C Review 风险和降级文案。

## 5. 依赖与协作

A 提供稳定 HTTP、存储与配置，B/C 提供共同 fixture；新状态/字段先读接口和决策记录再同步类型。
新页面/E2E 命令需要接入工作流，当前 CI 不会自动发现新增浏览器测试。新增依赖说明用途并更新锁文件。

## 6. 自己必须完成的测试

页面状态、分页和请求竞态、任务→报告导航、重试状态、长文本安全展示、真实内部链路、启动/重启与持久化。
前端运行 TypeScript/build 和新增测试命令；容器实测要记录环境与结果，不因存在 Dockerfile 就宣称部署通过。
