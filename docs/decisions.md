- 提供有证据的潜在风险与局部逻辑意见，由人工判断，不保证整个 PR 正确。
- 自动总体评论配合网页历史；AI 不可用时保留静态结果，明确说明审查不完整。
- 模块化单体、公共模型与 Protocol；不执行 PR 代码，不训练模型，不提前引入复杂基础设施。
- 五周按目标推进，每周对齐调整；各成员写自己的单测，D 负责跨模块验证。

## Q-03：预算只保留为讨论初值

可先讨论：每次至多 10 个 Python 文件、500 个增删行；每侧全文 200 KiB；模型上下文约 50,000 字符并另验 token；
单 worker 同时运行 1 个审查、队列至多 10 个；运行总预算 120 秒，页面约 3 秒轮询。
这些不是实测指标、现有配置或性能承诺。模型和费用上限需测量后确认。

超限要说明未处理范围；不能截断 Python 全文后假称 AST 完整。运行超时后不接受迟到结果继续发布。
同步线程不能靠 async 超时可靠强杀，仍需限制输入，并在保存/发布前检查任务有效性。重试退避应包含在总预算内。

## Q-05：现有接口与拟议升级

### 降级完成

当前 Task/Report 没有 degraded。建议 Task 增加该终态，Report 也增加 degraded，D 同步类型、页面与轮询。
completed 不带 error；failed 必须有 error；degraded 必须有说明限制的 diagnostics，可带相关 error。

| 情况 | 建议处理 |
|---|---|
| 分析完整、AI 有效 | completed，合并有效发现 |
| 分析部分受限但仍可用 | degraded，在有效范围审查并说明缺失 |
| 分析可用、AI 超时/无效 | degraded，保留静态结果；即使为空也说明 AI 未完成 |
| 模型部分意见非法 | 丢弃非法项，保留有效项并说明限制 |
| 整体分析失败、无可用结果 | failed，不调用模型；无 Python 文件明确为不适用 |
| 结果已保存、评论失败 | 保留审查终态，单独标发布失败 |

普通信息诊断不一定导致降级，由 A/C 明确哪些表示覆盖损失并加测试。

### 完整快照与去重

PR 数据已有 base/head，但当前 Task/Report 只有 head。建议后两者也增加必填 base_sha，唯一键使用 repository/PR/base/head。
相同快照返回原任务；base 或 head 改变都创建新任务，避免 base 变化后误用旧 Diff。
run 使用已保存的固定快照；原快照清理后只能按原 SHA 重取，无法取得则报 SNAPSHOT_UNAVAILABLE，不悄悄切到新版本。

### 事务保存

当前两个独立 save 方法不能自动保证一致性。建议评审以下存储端口变化后，再修改 Protocol：

```text
create_if_absent(task, pr) -> (task, created)   # 一次事务写快照和 queued 任务
get_snapshot(task_id) -> PullRequestData | None
finish(task, report) -> None                  # 一次事务写报告与终态
```

finish 校验 task_id/base/head 一致。数据库写失败不能继续发布评论，也不能承诺错误状态本身一定已成功落库。
存储至少需要任务、受限快照、报告、已受理 delivery 的记录。单进程重启将遗留任务标中断，不宣称有可靠分布式队列。

## Q-07：输入与重试

先用仓库+PR 编号。若支持链接，只解析明确支持的 GitHub PR 路径，不抓取任意网址。
拟议新增 POST /api/v1/tasks/{task_id}/retry，scope 为 review 或 publication，受理返回 202 ReviewTask。

- review：failed/degraded 且快照可用、未过时；复用任务 ID；queued/running/completed 拒绝重复重跑。
- publication：审查完成或降级、报告存在且发布失败；只重发评论，不再调用 AI；过时结果不重发。

首版不必做完整重试历史表。旧报告可保留到新结果原子替换；重试运行中，页面把它标为“上次结果”。
重复点击必须并发防护；404/409/422/503 等沿用安全错误结构。当前路由尚不存在。

<a id="q09"></a>

## Q-09：评论与旧快照

建议每 PR 一条当前系统身份发布的汇总评论，稳定标记例如 `<!-- coderisk:summary:v1 -->`，正文带任务和 base/head；网页保留各快照报告。
这将细化现有 Protocol 中 task/head 标记的粗约定；不得修改人工评论。

发布前重新核对 PR 当前快照，可识别为旧结果则只留历史，发布为 not_requested 并记录 STALE_SNAPSHOT。
发布串行化，重试先查已有评论，防止网络超时后重复新增。GitHub 更新和写评论不能由本地事务原子锁住，因此正文始终写明确 SHA。
正常/降级报告自动回写，降级要明显说明；纯失败建议仅网页显示，待讨论。没有公网详情地址时，不向别人发布 localhost 链接。
